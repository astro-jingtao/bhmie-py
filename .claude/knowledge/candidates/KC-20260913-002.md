topic: cmd-oneliner-percent-var-parse-time-expansion
type: fact

claim: >
  In a single `cmd /c 'a && set VAR=%VAR%;x && b'` chain, %VAR% is expanded
  when the whole line is parsed — before earlier commands in the chain have
  run — so appending to a variable set by an earlier command in the same
  chain silently overwrites it with an empty prefix; use a .bat file (parsed
  line by line) or delayed expansion (!VAR!) instead.

evidence:
  - "symptom: `cmd /c 'call vcvarsall.bat x64 && activate bhmiepy && set LIB=%LIB%;<flang-dir> && pip install -e .'` failed meson sanity check with 'LNK1104: 无法打开文件 libcmt.lib' (Chinese VS locale for 'cannot open file libcmt.lib') — i.e. the MSVC/SDK paths vcvarsall had put in LIB were gone"
  - "%LIB% was undefined at parse time (PowerShell parent had no LIB), so the set produced ';C:\\...flang-dir' only, clobbering vcvarsall's value"
  - "moving the identical sequence into scripts/dev-install.cmd (batch files expand per-line at execution time) made the same build succeed"
  - "documented cmd behavior: percent expansion happens at parse time per command line; delayed expansion (!VAR!) or separate lines avoid it (cmd /? and setlocal /? documentation)"
