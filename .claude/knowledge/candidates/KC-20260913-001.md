claim: >
  To build a Python Fortran extension with f2py + meson-python on Windows
  using conda-forge flang, install flang AND the separate flang-rt_win-64
  runtime package, wrap the whole build in a .bat script that activates
  vcvarsall x64 + the conda env and exports AR/RANLIB=llvm-*, the flang
  resource-dir on LIB, and FFLAGS=-static-libflangrt, and declare the f2py
  custom_target in the ROOT meson.build with every implementation-bearing
  Fortran source also listed as an extension_module source.

evidence:
  - "conda solve failed: PackagesNotFoundError fortran_metapackage on win-64; conda search showed package name is 'flang' (LLVM Flang 21-23)"

## Notes for skill-forge

The procedure has two halves that belong together (both were needed to get a
green build): (A) environment/toolchain setup on Windows conda (flang +
flang-rt_win-64 + VS BuildTools + env vars AR/RANLIB/LIB/FFLAGS, why each is
needed, and why it must be a .bat script — see KC-20260913-002), and (B)
meson.build wiring for f2py (root-level custom_target with exact generated
filenames, ASCII-only sources, implementation sources must be extension
sources). Project-specific instance of the whole recipe lives in
bhmiepy: scripts/dev-install.cmd + meson.build + CLAUDE.md for cross-checking.
